Como um modelo gera texto

Um modelo de linguagem só sabe fazer uma coisa: olhar um texto e dar a probabilidade do próximo token. Para escrever uma resposta, ele repete isso muitas vezes. Esta página mostra as quatro peças desse processo e onde o tempo vai.

Pergunta da semana

Por que ler uma pergunta de 500 tokens é mais rápido que escrever uma resposta de 500 tokens?

01

O laço: um token por vez

Cada clique é uma passada inteira pelo modelo. Ele devolve uma lista de probabilidades, um token é escolhido e volta para o fim do texto. A próxima passada já enxerga esse token. É por isso que a resposta sai em fila: o token 3 não existe antes do token 2.

02

Ler e escrever: duas fases

O prefill lê o prompt inteiro numa passada só: os tokens já existem, então passam juntos. O decode escreve a resposta com uma passada por token. Em toda passada, os pesos do modelo inteiro viajam da memória até o processador. Mude o modelo, o formato e a máquina e veja o que acontece com o tempo.

03

KV cache: não refazer o passado

Para escolher o próximo token, a atenção compara o token novo com todos os anteriores, usando dois vetores de cada um: K e V. Eles não mudam depois de calculados, porque um token só olha para trás. Então dá para guardar. Clique em "Próximo passo" e compare.

Troca conta por memória

Sem cache, o passo n reprocessa os n tokens: o trabalho total cresce com o quadrado do tamanho do texto. Com cache, cada passo processa só o token novo.

O preço é memória: 2 × camadas × cabeças KV × dimensão × bytes por token. No Qwen2.5-0.5B dá 12 KB por token; no Llama-3.1-8B, 128 KB.

Os números grandes ao lado usam o modelo e os tamanhos escolhidos na parte 02.

O que o cache não resolve: os pesos continuam sendo lidos inteiros a cada token. É por isso que, mesmo com cache, escrever continua mais lento que ler.

04

Sampling: das notas à palavra

O modelo não escolhe o token: ele dá uma nota (logit) para cada um dos ~150 mil tokens do vocabulário. O softmax transforma as notas em probabilidades, e o sampling sorteia. Os botões abaixo são os mesmos do Ollama e do llama.cpp.

Frase

Logits inventados para o exemplo, com a forma típica de uma saída real. Escolher o token é ordenar uma lista pequena: custa quase nada perto da passada pelo modelo.

05

A resposta

Ler = 1 passada

Tokens juntos

A pergunta já existe inteira. Os 500 tokens passam juntos: os pesos viajam da memória uma vez e servem a todos. O processador faz conta de matriz, que é o que ele faz melhor.

Escrever = 500 passadas

Tokens em fila

Cada token depende do anterior. Em cada passada, todos os pesos viajam para calcular um token só. O processador passa o tempo esperando a memória.

O KV cache ajuda, não resolve

O passado fica guardado

Evita recalcular os tokens antigos, mas não evita reler os pesos a cada token. E o sampling quase não custa nada.
