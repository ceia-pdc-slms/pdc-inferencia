2. Dockerfile modelo

Salve com o nome Dockerfile, sem extensão, na pasta do projeto. O exemplo é em Python; para outra linguagem mudam a imagem base e o comando de instalar.

Dockerfile
# 1. De onde parto: uma imagem que já traz a linguagem instalada
FROM python:3.12-slim

# 2. Pasta de trabalho dentro do container
WORKDIR /app

# 3. Dependências primeiro: se elas não mudarem, o Docker reaproveita esta etapa
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 4. O resto do código
COPY . .

# 5. Porta em que o programa atende (apague se ele não for um servidor)
EXPOSE 8000

# 6. O que roda quando o container liga
CMD ["python", "main.py"]

OutraProcure a imagem oficial da linguagem no Docker Hub e escolha uma etiqueta com número de versão, nunca latest.

Crie também um arquivo .dockerignore ao lado. Ele lista o que não deve entrar na imagem: deixa o pacote menor e evita copiar senhas.

3. compose.yaml modelo

Você só precisa dele em dois casos: quando há mais de um container trabalhando junto, ou quando o comando docker run ficou comprido demais para digitar toda vez. O modelo traz um programa seu e um banco de dados; apague o que não usar.

compose.yaml
services:
  app:                          # nome do seu container; os outros o encontram por este nome
    build: .                    # monta a imagem com o Dockerfile desta pasta
    ports:
      - "8000:8000"             # porta do computador : porta do container
    environment:
      MINHA_VARIAVEL: valor     # recados para o programa
    volumes:
      - ./dados:/app/dados      # pasta do computador : pasta do container
    depends_on:
      - banco                   # liga o banco antes (apague se não houver)

  banco:                        # segundo container, com imagem pronta
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: TROQUE-ESTA-SENHA
    volumes:
      - banco_dados:/var/lib/postgresql/data   # disco que não se apaga

volumes:
  banco_dados:

5. Prompt para pedir a um agente

Abra o agente de IA na pasta do projeto, preencha os colchetes e cole. O que você não souber, apague: o prompt manda o agente descobrir no código ou perguntar.

prompt
Quero rodar este projeto em Docker. Sou iniciante em Docker, então explique em linguagem simples.

O que eu sei sobre o projeto:
- O que ele faz: [descreva em uma frase]
- Como eu rodo hoje no meu computador: [comando, por exemplo "python main.py"]
- Porta em que ele atende, se for um servidor: [número ou "não sei"]
- Dados que não podem se perder quando o container for apagado: [pastas ou arquivos, ou "nenhum"]
- Outros serviços de que ele depende: [banco de dados, outro programa, ou "nenhum"]
- Meu sistema: [Windows, macOS ou Linux]

O que eu preciso que você faça:
1. Leia o projeto antes de escrever qualquer coisa: descubra a linguagem, a versão, as dependências e o comando de partida. Se algo importante não estiver claro, me pergunte em vez de supor.
2. Escreva um Dockerfile. Use uma imagem base oficial com versão fixa (nunca "latest"), instale as dependências antes de copiar o código e coloque um comentário curto em cada linha dizendo para que ela serve.
3. Escreva um .dockerignore que deixe de fora o controle de versão, ambientes virtuais, caches e qualquer arquivo com senha ou chave.
4. Só crie um compose.yaml se houver mais de um container ou se o comando para rodar ficar comprido. Se criar, comente cada bloco e use volumes para os dados que eu disse que não podem se perder.
5. Não escreva senhas nem chaves dentro dos arquivos. Use variáveis de ambiente e me diga quais eu preciso definir.
6. Construa a imagem e rode o container para confirmar que funciona. Se não puder executar comandos, diga isso claramente e não afirme que funcionou.
7. No fim, me entregue: a lista dos arquivos criados, os comandos exatos para construir, rodar, ver os registros e parar (prontos para copiar, no formato do meu sistema), como eu confirmo que deu certo, e o que você não conseguiu verificar.

Não mude o código do projeto sem me avisar antes.

6. Quando dá erro

O que apareceO que quer dizerO que fazer
Cannot connect to the Docker daemon ou error during connectO Docker não está ligado.Abra o Docker Desktop e espere ele terminar de iniciar.
port is already allocatedOutro programa já usa essa porta do computador.Troque o número da esquerda em ports, por exemplo "8001:8000".
COPY failed ou not found durante o buildO arquivo não está na pasta, ou está no .dockerignore.Confira o nome e rode o comando dentro da pasta do projeto.
O container liga e desliga logo em seguidaO programa terminou ou deu erro ao iniciar.Leia a mensagem com docker logs.
Uma variável chega vazia no containerEla foi criada em outro terminal.Defina a variável e rode o comando no mesmo terminal.
